اسکیل الگوهای بک‌اند

قواعد امنیتی کامل: اسکیل security. گیت کیفیت هر تسک بک‌اند: npx tsc --noEmit + eslint فایل‌های خودت + تست زنده curl (الگوی بخش ۶).

۱) زنجیره ثابت — هیچ لایه‌ای حذف نمی‌شود

// src/app/api/<domain>/route.ts — فایل نازک؛ منطق اینجا ممنوع
export async function POST(req: NextRequest) {
  try {
    await connectDB();
    const actor = requireRole(req, ["system_boss"]);
    assertCsrf(req);
    const body = await readJson<Record<string, unknown>>(req);
    return ok(await domainController.adminSave(body, actor, req));
  } catch (error) { return fail(error); }
}
// پارامتری: { params }: { params: Promise<{ id: string }> } → const { id } = await params;
  • کنترلر: بدنه را می‌خواند، فیلد الزامی را چک می‌کند، سرویس را صدا می‌زند، ok() برمی‌گرداند. خطا همیشه fail(error) — هرگز throw خام به بیرون.
  • سرویس: منطق واقعی. ورودی با parseInput پاک‌سازی می‌شود.

۲) گاردها

گارد کِی
requireAuth(req) / requireRole(req, [roles]) هر اندپوینت غیرعمومی — payload کاربر را برمی‌گرداند ({id, role, firstName})
assertCsrf(req) هر متد تغییردهنده (POST/PUT/PATCH/DELETE) — هدر سفارشی که fetcher کلاینت خودکار می‌فرستد
assertStaff / assertBoss داخل سرویس وقتی لایه route فقط requireAuth است
ریت‌لیمیت با IP limitByIp(req, "key", n, min) + نسخه‌ی بازدیدکننده برای اندپوینت‌های عمومی
ریت‌لیمیت با شماره OTP login/setup

۳) ورودی — readJson + parseInput (بدون اعتماد به کلاینت)

function parseInput(b: Body): Body {
  const out: Body = {};
  if (b.title !== undefined) out.title = txt(b.title, 200);       // الزامی: خالی = throw
  if (b.metaTitle !== undefined) out.metaTitle = txt(b.metaTitle, 200);
  if (b.rating !== undefined) out.rating = clampNum(b.rating, 1, 5, 5);
  if (b.consentSigned !== undefined) out.consentSigned = bool(b.consentSigned) ?? false;
  return out;
}
  • $set جزئی: فقط فیلدهای ارسالی در data می‌روند → findByIdAndUpdate(id, { $set: data }) — ویرایش partial امن است.
  • استثنا: زیرسند کامل (مثل شیء سئو) کل زیرسند را جایگزین می‌کند — فرم/عامل باید آن را کامل بفرستد (اول سند را با read بخواند).
  • searchOr(["name","quote"], q) برای جستجوی متنی؛ pageParams(sp, default, max) + paginate() برای فهرست‌ها → پاسخ {items,total,page,totalPages}.
  • شناسه: mustId(id, "نام موجودیت") — پیام فارسی + ۴۰۰ تمیز، نه ۵۰۰.

۴) قواعد نوشتن

  1. هر اقدام حساس AuditLog می‌شود: logAudit({ req, actorId, actorName, action: "create|update|delete|...", entity, entityId, before, after, meta }) — قبل از تغییر، before را .lean() بگیر.
  2. بعد از هر نوشتن مؤثر روی صفحات عمومی: revalidatePath("/") یا مسیرهای متأثر (+ revalidatePath("/sitemap.xml") برای محتوای ایندکس‌پذیر) داخل try{}catch{}.
  3. حذف = حذف واقعی (سخت) با snapshot در AuditLog — اگر soft-delete لازم شد، صریح تصمیم‌گیری و مستند شود.
  4. کلید Idempotency برای هر نوشتن قابل‌تکرار از کلاینت/عامل: consumeIdempotencyKey(req, "bucket") → در catch هم releaseIdempotencyKey فراموش نشود.
  5. قواعد دامنه‌ای سفت: مثال‌های مرجع — نظر بدون رضایت‌نامه انتشار نمی‌شود؛ هیچ نظری بی‌نام نیست؛ پیام چت همیشه با REST ارسال می‌شود (WS فقط پوش).
  6. همه پیام‌های خطا فارسی و کاربر-محور — Errors.badRequest/notFound/... یا new ApiError(400, "…", "CODE").

۵) مالکیت دیتا

  • مدل‌ها به تفکیک دامنه: auth / crm / finance / content / academy / system / chat / broadcast / media / backup.
  • اسکیمای مشترک سئو (ContentSeo زیرسند: canonical/noindex/og*/jsonLd) برای هر محتوای ایندکس‌پذیر.
  • مهاجرت داده نیازمند scripts/ + هماهنگی در برد — دیتابیس پروداکشن واقعی است.

۶) تست زنده E2E — الگوی استاندارد (بدون تکیه بر حدس)

الگوی کامل که در جلسه‌های واقعی جواب داده:

  1. ورود تستی مدیر: درخواست OTP → devCode در پاسخ (فقط dev) → login — کوکی‌ها را از set-cookie جمع کن. روی 429: ثانیه‌های پیام را parse و صبر کن.
  2. سناریو را با curl/node بزن (ساخت → ویرایش → تاگل → حذف) و persistence واقعی را با GET بعدی چک کن — «200 گرفتن» کافی نیست.
  3. NEG test: id ناموجود → ۴۰۴، id خراب → ۴۰۰ تمیز؛ قانون دامنه (مثلاً انتشار بدون رضایت‌نامه) → ۴۰۰ با پیام فارسی.
  4. هیچ mutation روی داده واقعی بدون مسیر پاکسازی/برگرداندن انجام نشود.
  5. گیت نهایی: npx tsc --noEmit صفر + eslint فایل‌های خودت صفر (قبل از کامیت، هر دو).

۷) چک‌لیست قبل از کامیت بک‌اند

  • زنجیره کامل route→controller→service و هیچ منطقی در route نیست
  • گارد نقش + CSRF + ریت‌لیمیت (عمومی) + AuditLog
  • parseInput whitelist — هیچ فیلدی مستقیم از body به DB نمی‌رود
  • revalidatePath صفحات متأثر
  • NEG tests تمیز (۴۰۰/۴۰۴ نه ۵۰۰) + E2E persistence
  • tsc + eslint صفر + برد به‌روز + کامیت طبق اسکیل commit

Production Deploy Runbook — اجرا، استقرار، راستی‌آزمایی

جمع‌بندی تجربه‌ی عملی استقرار Next.js روی ویندوز. قواعد پورت و سیکل دیپلوی باید با سیاست مدیر پروژه هماهنگ باشد و تغییراتش مستند.

۱) پورت dev/پروداکشن — مالکیت و تصاحب

  • پورت اصلی = بیلد پروداکشن (next start)، هرگز next dev.
  • اگر پورت اشغال بود: پیدا کن، بکش، خودت بالا بیاور:
    netstat -ano | grep ":3000" | grep LISTENING        # PIDها
for pid in $(netstat -ano | grep ":3000" | grep LISTENING | awk '{print $NF}' | sort -u); do taskkill //PID $pid //F; done
  • هرگز دو سرور روی یک پورت نباشد — دو پروسه‌ی هم‌زمان = BUILD_ID از .next خراب می‌شود/UI ناقص لود می‌شود. علامت بیماری: چند PID روی پورت + ls .next/BUILD_ID خالی → کلین‌بیلد از نو.
  • پروسه‌های بک‌گراند npm/next start گاهی «exit 1» گزارش می‌شوند درحالی‌که سالم‌اند — همیشه با curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/ تصمیم بگیر، نه با status تسک.

۲) سیکل دیپلوی (توقف → بیلد → استارت)

بیلد روی سرورِ در حال اجرا ممنوع — ویندوز روی فایل‌های .next قفل می‌گذارد و بیلد/استارت دوم با «Could not find production build» می‌میرد. ترتیب همیشه:

# ۱) توقف
for pid in $(netstat -ano | grep ":3000" | grep LISTENING | awk '{print $NF}' | sort -u); do taskkill //PID $pid //F; done
# ۲) بیلد
npm run build
# ۳) استارت (بک‌گراند) — فقط یک پروسه روی پورت
npx next start
# ۴) تأیید
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/     # 200
  • اگر خروجی بیلد دوپهلو بود («Compiled successfully» و «Failed» با هم) — اجرای مجدد تمیز بگیر؛ اغلب خروجی نیمه‌کاره‌ی یک اجرای قطع‌شده است.
  • خروجی «Failed to compile» واقعی = دوباره npm run build 2>&1 | tail -25 بگیر و خطا را بخوان.

۳) راستی‌آزمایی — قبل از هر کامیت

  1. npx tsc --noEmit → صفر خطا.
  2. npx eslint <فایل‌های دست‌خورده> → صفر خطا (هشدارهای قدیمی‌شناخته اشکال ندارد).
  3. سئو: اسکریپت چک سئوی پروژه را روی سرور لوکال اجرا کن (robots، متاها، X-Robots-Tag، 404 واقعی).
  4. بصری: مرورگر in-app — دسکتاپ ۱۴۴۰×۹۰۰ + موبایل ۳۹۰×۸۴۴، اسکرین‌شات؛ برای اندازه‌گیری دقیق از tab.playwright.evaluate استفاده کن (عدد بده، حدس نزن).
  5. تست تعاملی (کلیک/فرم): اگر locator با نام فارسی timeout خورد، دوباره همان را retry نکن — tab.playwright.evaluate با document.querySelector(...).click() قطعی‌تر است، یا کلیک با مختصات از اسکرین‌شات تازه.

سرور موقت موازی (بدون دست زدن به پورت اصلی)

NEXT_DIST_DIR=.next-verify npx next build     # خروجی جدا — در .gitignore است
NEXT_DIST_DIR=.next-verify npx next start -p 3100
# بعد از کار: هر PID لیسنر 3100 را taskkill کن

پورت اصلی برای تغییرِ env/CSS فقط با بیلد+ری‌استارت خودش به‌روز می‌شود.

۴) دیتابیس — بکاپ و مهاجرت

  • دیتابیس پروداکشن معمولاً لوکال است؛ رشته‌ی اتصال فقط از .env خوانده شود.
  • بکاپ: اگر mongodump نصب نیست، اکسپورت JSON همه کالکشن‌ها به backups/db-<timestamp>/ (اسکریپت کوتاه با connectDB + mongoose.connection.db.collections()). پوشه backups/ در .gitignore — دیتای کاربران دارد، هرگز کامیت نشود.
  • اسکریپت‌های مستقل tsx: .env را خودشان باید لود کنند (tsx خودش نمی‌خواند) و در پایان mongoose.connection.close() یا process.exit() — وگرنه پروسه باز می‌ماند و «هنگ» به نظر می‌رسد.
  • مهاجرت داده: همیشه اول dry-run، بعد --write؛ الگوی idempotent (upsert با کلید یکتا).

۵) سئو — قواعد حیاتی

  • NEXT_PUBLIC_SITE_URL هرگز localhost نماند — اگر robots.ts حالت staging داشته باشد، با URL لوکال کل سایت Disallow: / می‌شود + canonical/sitemap لوکالی می‌شوند. (NEXT_PUBLIC_* در build اینلاین می‌شود → تغییرش = بیلد مجدد.)
  • ریدایرکت‌های غیرASCII در next.config باید encodeURI(from) باشند — Next فاز redirects را روی مسیر percent-encoded مقایسه می‌کند.
  • فونت فارسی با display:"swap" + preload — سقف ۴ وزن.
  • گیت سئو: چک‌لیست robots، متای صفحات، X-Robots-Tag روی /api و 404 واقعی.

۶) دام‌های شناخته‌شده (هرکدام یک بار گاز گرفته‌اند)

  • CSS cascade: override فقط-موبایل را همیشه بعد از قانون پایه بنویس؛ قانون هم‌وزنِ قبلیِ فایل می‌بَرد. قانون base معمولاً پایین‌تر از جایی است که فکر می‌کنی.
  • .gitignore: خط با \n لفظی = قانون بی‌اثر. بعد از هر افزودن، git status را چک کن.
  • sed با متن فارسی/یونیکد روی این ماشین می‌شکند (ugrep alias + یونیکد) — از ابزار Edit استفاده کن؛ برای grep الگو با grep -oe 'pattern'.
  • تصاویر: next/image پیش‌فرض lazy — فقط LCP واقعی priority بگیرد.

۷) گیت — قرارداد کامیت/پوش

  • کامیت‌های conventional: feat|fix|style|refactor|docs|chore(scope): خلاصه انگلیسی.
  • قبل از کامیت npx tsc --noEmit.
  • سیاست پوش با دستور مدیر مستند شود (پوش آزاد، فقط با دستور، یا از دیپلوی خودکار).
  • وقتی ایجنت دیگر هم‌زمان در کلون کار می‌کند: فایل‌های خودت را صریح add کن (نه add -A) مگر مدیر گفته باشد «همه‌چیز را کامیت کن» — آن‌وقت یک کامیت جدا با توضیح «agent work» بده.
  • فایل‌های مشترک حساس: .env هرگز؛ فایل‌های استایل/برد نقطه تماس دو ایجنت‌اند — قبل از کامیت git diff آن‌ها را نگاه کن که کار طرف دیگر را قاطی نکنی.

Next.js SEO — Complete Google Optimization Guide

Implement production-grade Google SEO in Next.js (Node.js) projects. This skill encodes Google Search Central documentation plus current Next.js (v15/v16, App Router first) conventions into a review-and-implementation workflow.

How Google Search Works (30-second mental model)

Google processes every URL in four stages. Every SEO task maps to one of them:

  1. Crawl — Googlebot discovers URLs via links, sitemaps, and previously known URLs. robots.txt, noindex, and server errors control this.
  2. Render — Googlebot executes JavaScript with an evergreen Chromium (Web Rendering Service). SSR/SSG pages render instantly; JS-only content enters a slower second wave. Server-rendered HTML is always safer.
  3. Index — Google parses the rendered HTML, resolves canonicals, groups duplicate URLs, and stores content. <link rel="canonical">, noindex, and hreflang act here.
  4. Rank — Helpful-content signals, relevance, links, page experience (Core Web Vitals), and spam policies determine position.

Rule of thumb: ship real content in the initial HTML response, describe every page with unique metadata, remove crawl/index blockers, and keep the page fast and stable.

Core Workflow

When building or auditing a Next.js project, work through these steps in order:

Step 1 — Establish the base (every project)

// app/layout.tsx — root layout
import type { Metadata, Viewport } from 'next'

const SITE_URL = 'https://example.com' // single source of truth

export const metadata: Metadata = {
  metadataBase: new URL(SITE_URL), // resolves all relative URLs — REQUIRED for OG images
  title: {
    default: 'Site Name — Primary value proposition',
    template: '%s — Site Name', // child pages only need `title`
  },
  description: 'Default site-wide description, 150–160 chars, unique per page when possible.',
  alternates: { canonical: '/' },
  openGraph: {
    type: 'website',
    siteName: 'Site Name',
    url: SITE_URL,
  },
}

export const viewport: Viewport = {
  width: 'device-width',
  initialScale: 1,
  themeColor: '#000000',
}

// app/page.tsx — home page
import type { Metadata } from 'next'
export const metadata: Metadata = {
  title: 'Home', // renders as "Home — Site Name" via template
  alternates: { canonical: '/' },
}

Key API facts:

  • metadata = static export; generateMetadata() = dynamic, receives awaited params/searchParams (Next 15+: they are Promises).
  • Metadata only works in Server Components. Next always adds charset and viewport meta tags automatically.
  • Merge rules: fields are shallow-merged from root layout down. A child's title overrides the parent's whole title object; openGraph.title falls back to title when omitted.
  • themeColor/viewport inside metadata are deprecated since Next 14 — use the viewport/generateViewport exports.
  • Next 15.2+ streams metadata for human users but emits blocking <head> metadata for bots (Googlebot, Bingbot, Twitterbot…) — configurable via htmlLimitedBots. Bots still see correct tags; do not panic when you see tags in <body> for a non-bot UA.
  • Next 16: params/searchParams must be awaited; Turbopack is default; middleware.ts → proxy.ts; Cache Components model with "use cache".

Step 2 — Control crawling and indexing

  • app/robots.ts → generates /robots.txt (allow public paths, block /api, admin, search results pages).
  • app/sitemap.ts → generates /sitemap.xml from your routes/CMS (split with generateSitemaps beyond 50,000 URLs).
  • Canonical URLs: set alternates.canonical on every indexable page, especially filtered/sorted/paginated variants.
  • Block indexing with robots: { index: false } (meta robots) — never with robots.txt (Google explicitly does not support noindex in robots.txt).
  • Non-HTML resources: use the X-Robots-Tag HTTP header via next.config.ts headers().
  • Redirects: permanent: true (308/301) for moved content, temporary otherwise; declare in next.config.ts.

Non-Negotiable Rules

These prevent the most common, highest-impact failures seen in real Next.js projects:

  1. One canonical URL per page. Missing or self-conflicting canonicals dilute ranking across ?filter=, trailing-slash, and http/https variants.
  2. Never rely on robots.txt to de-index. noindex belongs in meta robots or X-Robots-Tag. Blocking via robots.txt hides the page from the crawler but leaves the URL indexed "without content".
  3. Set metadataBase in the root layout. Without it, OG image URLs warn or resolve wrong; social cards break silently.
  4. Every indexable page needs a unique title + description. Templated or duplicated descriptions get rewritten by Google; titles get truncated past ~600 px.
  5. Server-render indexable content. Content only mounted after user interaction or fetch-on-client is invisible until render — often never indexed.
  6. priority the LCP image, sizes every image. Wrong sizes wastes bandwidth; missing priority on the hero image tanks LCP.
  7. JSON-LD must mirror visible content. Structured data describing invisible/fabricated content violates Google's spam policies.
  8. Await params/searchParams. Next 15+ they are Promises; sync access throws at build.
  9. Keep viewport out of metadata. Use the viewport/generateViewport export (deprecated-in-14 fields still render but warn).
  10. Use 308/301 (permanent: true) for content moves, and only one redirect hop. Chains leak PageRank and delay crawls.

Launch-Ready SEO Checklist (condensed)

  • metadataBase + title template + default OG in root layout
  • Unique title/description/canonical per indexable route
  • robots.ts allows pages, blocks /api, /admin, internal search
  • sitemap.ts lists all canonical, indexable URLs with lastModified
  • JSON-LD for site type + BreadcrumbList on nested pages
  • opengraph-image per key route (1200×630) + favicon/icon set
  • next/image with sizes; priority on hero; next/font for all text
  • noindex on utility pages (404 intentionally excluded, thank-you, admin)
  • 301 redirects map for any moved/renamed routes
  • hreflang alternates.languages + x-default if multi-language
  • Verified in Search Console; sitemap submitted; zero "Page indexing" errors
  • PSI field data: LCP < 2.5 s, INP < 200 ms, CLS < 0.1
