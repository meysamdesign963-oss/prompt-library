Responsive Frontend Standards

استاندارد اجباری ریسپانسیو برای دسکتاپ و موبایل/اندروید — مقیاس گرید، پدینگ، اسپیسینگ، بریک‌پوینت‌ها و اندازه لمسی. در ساخت و ویرایش هر صفحه و کامپوننتی همیشه با همین مقادیر اعمال شود.

UI & Design Ready 1.0.0 responsive · tailwind

اسکیل استاندارد فرانت‌اند — گرید، پدینگ و اسپیسینگ

مبنا: Mobile-First با TailwindCSS 4. هر صفحه و کامپوننت باید در موبایل/اندروید (عرض ۳۲۰px به بالا) و دسکتاپ هر دو درست باشند. توکن‌های رنگ و فونت از دیزاین‌سیستم پروژه.

۱) بریک‌پوینت‌های استاندارد (فقط همین‌ها)

بریک‌پوینت عرض کاربرد
پایه (بدون پیشوند) 0–639px موبایل/اندروید — همه استایل‌ها اول برای همین نوشته می‌شوند
sm: ≥640px موبایل بزرگ / تبلت کوچک
md: ≥768px تبلت
lg: ≥1024px لپ‌تاپ / دسکتاپ
xl: ≥1280px دسکتاپ بزرگ

ممنوع: بریک‌پوینت سفارشی، max-[520px]: و مقادیر arbitrary مثل p-[13px]. فقط مقیاس استاندارد Tailwind (پایه ۴px: 1=4، 2=8، 3=12، 4=16، 5=20، 6=24، 8=32، 10=40، 12=48...).

۲) کانتینر و چیدمان صفحه

  • همیشه کانتینر استاندارد (mx-auto w-full max-w-7xl px-4 sm:px-6 lg:px-8) — پدینگ افقی دستی نگذار.
  • هیچ عنصری نباید overflow افقی بسازد؛ عرض ثابت px بزرگ ممنوع (حداقل عرض هدف: ۳۲۰px).
  • سرتیتر صفحه: کامپوننت هدر با mb-6.
  • فاصله عمودی سکشن‌های سایت: py-10 sm:py-14 lg:py-20 — داخل پنل: py-6.

۳) گرید استاندارد

الگو کلاس گرید
کارت‌های KPI / آمار grid grid-cols-1 gap-4 sm:grid-cols-2 xl:grid-cols-4
کارت‌های محتوا (وبلاگ، دوره، خدمات) grid grid-cols-1 gap-4 sm:grid-cols-2 sm:gap-6 lg:grid-cols-3
فرم‌ها grid grid-cols-1 gap-4 md:grid-cols-2 (فیلد تمام‌عرض: md:col-span-2)
جدول در پنل داخل wrapper با اسکرول داخلی یا تبدیل به کارت در موبایل
محتوا + سایدبار grid grid-cols-1 gap-6 lg:grid-cols-3 (محتوا: lg:col-span-2)

۴) پدینگ و اسپیسینگ استاندارد

محل مقدار
داخل کارت p-4 sm:p-6 (کارت فشرده p-4)
فاصله بین کارت‌ها و آیتم‌ها gap-4 (فشرده gap-3، باز gap-6)
فاصله فیلدهای فرم space-y-4 یا gap-4
دکمه (سایز md) px-5 py-2.5 با min-h-11
بین عنوان و محتوا mb-4 تا mb-6
آیتم‌های لیست داخل کارت space-y-3
مودال p-6 max-h-[88vh] overflow-y-auto

قاعده: اول از کلاس‌های آماده‌ی دیزاین‌سیستم خودت استفاده کن؛ کامپوننت جدید را دقیقاً با همین مقیاس بساز و به کیت اضافه کن.

۵) اندازه لمسی (اندروید)

  • هر عنصر کلیک‌پذیر حداقل min-h-11 (۴۴px) و فاصله دو هدف لمسی حداقل gap-2.
  • سایز sm دکمه (min-h-9) فقط برای اکشن‌های فرعی — در موبایل برای اکشن اصلی استفاده نشود.
  • لینک‌های منوی موبایل: تمام‌عرض با px-3 py-2.5.

۶) تایپوگرافی ریسپانسیو

نقش کلاس
تیتر صفحه سایت text-2xl sm:text-3xl lg:text-4xl font-bold (+ رنگ برند)
تیتر صفحه پنل text-xl font-bold
تیتر کارت / سکشن text-base sm:text-lg font-semibold
متن بدنه text-sm leading-6
کپشن / متا text-xs text-gray-500
اعداد مالی و جدولی کلاس اعداد لاتین

۷) RTL و فارسی

  • dir="rtl" سراسری در layout — تغییر دستی direction ممنوع (جز عناصر عددی).
  • فاصله‌ها با gap و space-* — نه mr-/ml- (در RTL می‌شکنند؛ اگر ضروری شد ms-/me- منطقی).
  • شماره تلفن، کد و ایمیل داخل متن فارسی: dir="ltr" روی همان عنصر.
  • تاریخ همیشه شمسی با یکتای تاریخ پروژه — تاریخ ISO خام به کاربر نمایش داده نشود.

۸) چک‌لیست هر صفحه / کامپوننت جدید

  • موبایل ۳۲۰px: بدون اسکرول افقی و بدون فشرده‌شدن محتوا
  • کانتینر درست: کانتینر استاندارد صفحه
  • گرید و اسپیسینگ فقط از جداول همین اسکیل
  • حالت لودینگ / خالی / خطا: کامپوننت‌های آماده‌ی پروژه (Skeleton / EmptyState / ErrorState)
  • هدف لمسی ۴۴px، تیترها مقیاس‌دار، اعداد مالی با کلاس اعداد لاتین
  • بدون استایل inline برای چیزی که توکن دارد (رنگ/فونت/شعاع از دیزاین‌سیستم)

۹) تست پرفورمنس — فقط روی بیلد production

اندازه‌گیری Lighthouse / Core Web Vitals هرگز روی npm run dev معنا ندارد — حالت dev (React توسعه، بدون minify، کامپایل آنی) TBT چند ثانیه‌ای می‌دهد (اندازه‌گیری واقعی: dev → TBT سه‌ثانیه‌ای 3,040ms با امتیاز 2 و پرفورمنس 42؛ production همان صفحه → TBT 190ms با امتیاز 90 و پرفورمنس 84).

  • مسیر درست: npm run build و بعد npm run start — تست فقط به آن سرور.
  • پیش‌فرض لایت‌هاوس موبایل با 4x CPU throttle است؛ اعداد دسکتاپِ بدون throttle قابل مقایسه نیستند.
  • پیش از هر نتیجه‌گیری پرفورمنسی، نسخه‌ی next dev بودن سرور تست را بررسی کن.
